# Регламент трёхуровневого тестирования (A4, встреча №3 10:55–15:37)

> Эксперт: «тестировать сначала по одному, потом умениями, а потом целиком».
> Исполнение — всегда в среде LangGraph (конституция п.11): уровень 1 —
> одноузловой подграф, уровень 2 — подграф-умение, уровень 3 — основной граф.

## 0. Предусловие: полная LangGraph-миграция

**Тестировать схему — только после того, как всё попало в LangGraph.**
«Эту схему нельзя тестировать до того, как всё попадёт в LangGraph, прям
нельзя — код прорастёт друг в друга» (дефундация). Признак готовности:
`python3 project/prove_langgraph.py` — **протокол доказательства** «ничего вне
LangGraph» (5 линий: AST-статика call-site, идентичность движка, инвентаризация
нод, шаги, эммитенные самим Pregel, инструментальный трассировщик + перехват
проб); `python3 project/run_tests.py --level 3` — инвентаризация подтверждает,
что каждая нода проекта — нода графа; исполнение мимо графа исключено
стражем «ничего вне графа» (`smoke_nothing_outside_graph.py`).

## Уровень 1 — модуль

Модуль тестируется **отдельным агентом с чистым контекстом**, сформированным
специально под задачу модуля («не тупой, а с подготовленным контекстом»).
Расточительно, но подтверждает: модуль **не нулевой** и выполняет заявленное
(а не только «не падает»).

Что делает раннер (`run_tests.py`):
1. Собирает **подготовленный контекст**: контракт модуля (имя, назначение —
   «отличимость»), подготовленный вход под задачу модуля (`PREPARED_INPUTS`).
2. Отдаёт контекст агенту через LM-провайдера (за внешним контуром) —
   сейчас детерминированный stub; с реальным `RAG_LM_PROVIDER=http` —
   полноценный агент-тестировщик с чистой головой.
3. Прогоняет модуль **по графу** (одноузловой подграф, `invoke_node`).
4. Проверяет контракт: статус `done`, `trace == [нода]`, ошибок нет,
   `predict()` неотрицателен; для `embed_chunks` — вектор на каждый чанк.

```bash
python3 project/run_tests.py --level 1
```

## Уровень 2 — умение

Подграф-умение вызывается как узел LangGraph: система смотрит, работает ли,
**собирает все ошибки и делает несколько циклов правки**; перед прогоном
текст **очанковывается** (чанки режутся под лимит входа эмбеддера — входные
ворота, B1).

```bash
python3 project/run_tests.py --level 2
```

Циклы правки: ошибка → агент с подготовленным контекстом предлагает правку →
повторный прогон (до `max_cycles`); при реальном LM-провайдере правки
применяются к данным/нода по вердикту агента.

## Уровень 3 — целиком

Полный прогон графа по всем маршрутам (check / index / refresh / status):
фактический `trace` сверяется с картой (`docs/node-map.md`), стражи не дают
нарушений, плюс инвентаризация «все ноды проекта — ноды графа LangGraph».

```bash
python3 project/run_tests.py --level 3
python3 project/run_skeleton.py      # холостой прогон, все четыре маршрута
```

## Дополнительные проверки (поверх графа)

| Проверка | Команда |
|---|---|
| Стражи: события, каскад самоописанности, отличимость | `python3 project/smoke_guards.py` |
| Страж «ничего вне графа» (первый обязательный) | `python3 project/smoke_nothing_outside_graph.py` |
| Провайдеры внешнего контура, WAL, замена SQLite→PostgreSQL | `python3 project/smoke_providers.py` |
